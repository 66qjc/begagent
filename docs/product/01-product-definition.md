# 01｜产品定义

> 状态：**Confirmed / 用户已确认**

本册只定义 `beg` 的产品问题、价值与范围。领域对象及其生命周期由[02｜领域模型](./02-domain-model.md)唯一拥有；Business Baseline 仍处于逐册确认阶段。

## 品牌与定位

`beg` 是有意选择的品牌词：求职者是在向组织争取一个并不天然属于自己的机会，而不是假装所有雇主都在等待自己。它承认这种现实的不对称，也帮助普通求职者更有准备地询问、证明、协商和持续行动。`beg` 不鼓励自我贬低或无差别乞求式投递；它表达的是在真实能力、现实限制和个人尊严之内，主动去争取合适机会。`beg` **不是** `B.E.G.` 的首字母缩写。

主要服务大学求职者：准备实习、校招或第一份职业选择的学生，尤其是经历零散、缺少表达与行动路径、希望跨方向或挑战目标机会的人。

### 首要用户边界

- 首要用户是仍在校、即将毕业或处于毕业初期的大学求职者；实习、校招和第一份正式工作是首要场景。
- 用户可以缺少成熟简历、完整职业目标或现成项目证据；产品必须允许从不完整信息开始，而不是把“资料齐全”作为使用门槛。
- 有多年职业经历的成熟求职者、企业招聘方、猎头和招聘平台不是当前首要用户。未来可以扩展，但不能让其需求稀释大学生求职主线。

## 要解决的问题与价值主张

大学求职者常同时面对四类断裂：真实经历难以形成可信证据、机会信息难以判断、申请与 HR 往来难以持续执行、差距难以转成可验证的成长成果。

`beg` 的价值主张是：帮助用户以经确认的事实与证据为基础，持续发现、准备、争取并复盘机会；在需要自动化时提供有效协助，在需要选择、承诺或交接时把控制权留给用户。

### 产品承诺

`beg` 对用户作出的是过程承诺，而不是 Offer 保证：让每项机会判断有来源，让每份材料有证据，让每次外部行动有授权和回执，让每次结果都能形成可审阅的下一步。系统可以提高准备与执行效率，但不能保证招聘结果，也不能把模型推断包装成用户能力。

## 长期产品蓝图

长期产品不是单点简历工具，而是一套围绕职业目标持续运作的求职协作系统。它把用户的个人事实、机会判断、申请执行、沟通记录、成长成果与结果反馈连成可回看的循环；用户可以从任何合适入口开始，并逐步补齐信息与授权。

### 四条价值链

| 价值链 | 用户获得的持续价值 |
|---|---|
| 简历 + 证据档案 | 把真实经历沉淀为可确认、可复用、可追溯的 `CandidateProfile` 与 `Evidence`，并生成适配机会的材料。 |
| 机会情报 | 汇集、辨识、比较和解释 Opportunity，优先使用官方或已获授权的来源。 |
| 申请 + HR 执行 | 将申请、跟进和 Conversation 组织为持续任务；在授权范围内协助执行并保留用户接管点。 |
| 成长追求 | 将真实差距转成 Growth Plan、行动和新证据，而不是用虚构表达掩盖缺口。 |

四个核心 Agent——`ProfileAgent`、`OpportunityAgent`、`ApplicationAgent`、`GrowthAgent`——分别围绕上述价值链承担清晰主责；领域专家为专业判断、材料复核或渠道知识提供支持。责任归属、交接与自动化的规范由后续分册定义，本册不把它们实现为具体框架或流程。

## 多入口、渐进式上手

用户不必先完成一份冗长档案才获得帮助。首入口严格只有四类：**简历／材料**、**岗位链接或文本**、**职业兴趣**（含成长目标、方向、行业、约束或目标公司）和**空白对话**。系统只在当前目标需要时请求更多信息，并清楚说明信息用途、证据状态与授权范围。

“开始申请”和“带来 HR 对话”不是新增首入口：它们只能在用户已从四类入口之一建档后，由 `Opportunity`／`JobPursuit`／`Application`／`Conversation` 流程产生或接续的 downstream deep-link。将来若导入既有申请或对话，也必须先按[03｜业务流程](./03-business-flows.md)归一化和审阅，不能绕过四类入口直接执行外部动作。

## 产品服务面

`beg` 的长期产品服务面由两部分组成：

- **Web Control Center**：用户理解目标、进度、证据、机会、待决事项与授权，并可以审阅、确认、暂停或接管。
- **Local Execution Bridge**：在用户设备与获授权环境中承接需要本地上下文、浏览器交接或受控执行的任务；它不是绕过平台规则的通道。

二者共同服务同一用户目标，但不把产品体验绑死在某个 Agent 框架或原型界面上。

## 长期蓝图与赛事切片

长期蓝图覆盖四条价值链与反复发生的职业周期。赛事切片固定选择以下路径：

`对话建档 → 大厂岗位发现 → 成长型 JobPursuit → Evidence Task → 简历与证据档案 → 独立复核／验证 → 授权投递 → 包络内 HR 自主沟通 → 包络外升级 → Outcome 回流`

该切片必须真实运行 `beg` 自己拥有的业务状态、结构化 Agent 产物、授权、幂等、恢复与 trace；岗位来源、ATS、HR 通道和 Local Execution Bridge 可以使用明确标注的受控 adapter。它不是长期产品的全部，也不应反过来限制后续蓝图。唯一完整的演示范围、受控边界和验收口径由[08｜赛事切片与验收](./08-contest-slice-acceptance.md)拥有。

## 非目标

- 不承诺代替用户作出职业、薪资、Offer 或其他高影响决定。
- 不把未经用户确认的推断写成事实，不伪造经历、成果、身份或证明。
- 不开展违反平台规则的批量投递、验证码规避、冒充或未获授权的自动化。
- 不把 `beg` 做成面向所有行业的通用 Agent 平台、招聘方 ATS、猎头 CRM 或岗位聚合门户。
- 不以“全自动”为目标牺牲信息新鲜度、授权、外部回执、失败恢复或用户接管能力。
- 不以隐藏的框架、提示词或聊天记录作为用户唯一可见的业务状态。
- 不把本册草案当作实施授权或框架选型结论。

## 成功结果

用户应能更快地把真实经历转为可信材料，更清楚地理解机会与差距，更连续地完成申请和沟通，并在每个关键承诺前保有知情、授权、暂停和接管能力。对产品而言，成功还意味着：效率提升不以真实性、来源合规、用户控制或长期成长为代价。
